Quick Start

This proxy forwards requests to the Anthropic Claude API using your Claude MAX subscription credentials. It supports both the native Anthropic API format and an OpenAI-compatible translation layer.

Requires a Claude MAX subscription. Authenticate via the button above or visit /auth/login.

Anthropic API (Native)

Send requests using Anthropic's native message format:

curl http://localhost:PORT/v1/messages \
  -H "Content-Type: application/json" \
  -d '{
    "model": "claude-sonnet-4-6",
    "max_tokens": 1024,
    "messages": [
      {"role": "user", "content": "Hello, Claude!"}
    ]
  }'

OpenAI-Compatible API

Use this as a drop-in replacement for OpenAI's chat completions API. Model names are automatically mapped to Claude equivalents.

curl http://localhost:PORT/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "claude-sonnet-4-6",
    "messages": [
      {"role": "user", "content": "Hello!"}
    ],
    "stream": true
  }'

Using with the OpenAI SDK

from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:PORT/v1",
    api_key="unused"  # any non-empty value
)

response = client.chat.completions.create(
    model="claude-sonnet-4-6",
    messages=[{"role": "user", "content": "Hello!"}]
)

Streaming

Both endpoints support SSE streaming. Set "stream": true in your request body. The OpenAI-compatible endpoint translates Anthropic's SSE events into OpenAI's chunk format.

Presets

Custom presets can inject system prompts and suffixes into requests. Place a JSON file in the server/presets/ directory and access it via the URL:

# Anthropic format
POST /v1/{preset_name}/messages

# OpenAI format
POST /v1/{preset_name}/chat/completions

Preset JSON format:

{
  "system": "Additional system prompt text",
  "suffix": "Suffix appended after last user message",
  "suffixEt": "Suffix used when extended thinking is enabled"
}

API Key Protection

Optionally restrict access by setting the API_KEY environment variable. When set, all non-auth requests must include it:

# Via Authorization header
Authorization: Bearer your-api-key

# Via x-api-key header
x-api-key: your-api-key

OpenAI Model Mapping

When using the OpenAI-compatible endpoint, these model names are translated automatically:

gpt-4o           -> claude-sonnet-4-6
gpt-4o-mini      -> claude-haiku-4-5-20251001
gpt-4-turbo      -> claude-sonnet-4-6
gpt-4            -> claude-sonnet-4-6
gpt-3.5-turbo    -> claude-haiku-4-5-20251001
o1 / o1-preview  -> claude-opus-4-6
o3               -> claude-opus-4-6
o3-mini          -> claude-sonnet-4-6
o4-mini          -> claude-sonnet-4-6
Unknown model names are passed through unchanged. Use exact Anthropic model names for best results.

server/config.txt

Configuration is loaded from server/config.txt on startup.

port=42069                       # Server port
host=                            # Leave blank for auto-detect
log_level=INFO                   # TRACE, DEBUG, INFO, WARN, ERROR
filter_sampling_params=false     # Resolve temperature/top_p conflicts
fallback_to_claude_code=true     # Use Claude Code credentials as fallback
auto_open_browser=true           # Open browser on first run

Environment Variables

API_KEY=your-secret-key    # Protect proxy with an API key

Token Priority

  • x-api-key header - If a request includes an Anthropic API key (sk-ant-*), it's used directly
  • OAuth tokens - From ~/.claude-code-proxy/tokens.json
  • Claude Code credentials - Fallback from ~/.claude/.credentials.json (if enabled)

Docker

docker-compose up

The Docker setup mounts ~/.claude and ~/.claude-code-proxy for credential persistence. The server auto-detects Docker and binds to 0.0.0.0.

Request Processing

  • Prepends a required system prompt identifying as Claude Code (required by the API)
  • Strips ttl from cache_control objects (not supported by this endpoint)
  • Optionally filters conflicting sampling parameters (temperature vs top_p)
  • Automatically refreshes expired OAuth tokens
